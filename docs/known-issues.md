미해결 상태로 추적 중인 문제 목록. 해결되면 항목을 제거하고 커밋 메시지에 명시한다.

## KI-1. 특정 한글 글자(예: `테`)가 다음 글자와 가로로 겹쳐 보임

- **상태:** 미해결 (해결 보류)
- **최초 보고:** 2026-06-13
- **증상:** `테` 등 일부 한글 글자가 바로 뒤 글자와 가로로 포개져 렌더링됨.
  - 제목(h1~h6)과 **평문 본문 모두**에서 발생 (제목 전용 문제 아님).
  - 예: `<--- 테스트` 에서 `---` 와 `테`, 그리고 `테`+다음 글자.
- **영향:** 시각적 가독성 저하. 기능 동작에는 영향 없음.

### 원인 아님으로 확인된 것 (배제됨)
- 제목 음수 자간(`letter-spacing: -0.012em`) — 평문에도 발생하므로 무관. (원복함)
- 제목 줄높이(`line-height`) — 가로 겹침이라 무관. (원복함)
- 제목 가변폰트 보간 굵기(`font-weight: 650`) — 700으로 바꿔도 동일. (650 유지)
- `text-rendering: optimizeLegibility` → `auto` 변경 — **효과 없음.** (원복함)
- 코드블럭 장평/`font-stretch`/`scaleX`/`letter-spacing`/`word-spacing` — 애초에 설정 없음.

### 유력 가설 (다음에 시도)
1. **PretendardVariable.woff2 폰트 자체의 글자 advance/메트릭 문제** 또는 WebKit(Tauri webview)에서의 가변폰트 메트릭 렌더 버그. → 비가변(static) Pretendard weight 파일로 교체해 비교, 또는 폰트 재추출.
2. WebKit 특정 버전의 한글 커닝/세이핑 버그. → `font-feature-settings: "kern" 0` 강제, 또는 `font-variant-ligatures: none` 시도.
3. 폰트 폴백 체인 문제(Pretendard 미적용 시 system-ui로 폴백). → 실제 적용 폰트 DevTools로 확인.

### 재현
- `render-test.md` 의 제목/본문 `테` 포함 구간. 라이트/다크 무관.

## KI-2. Windows에서 앱이 간헐적으로 통째로 죽음 (`tao` 이벤트루프 패닉)

- **상태:** 미해결
- **최초 보고:** 2026-07-17 (재현: 2026-07-21, 2026-08-10)
- **증상:** 로그 파일에 아래 패닉이 남고 프로세스가 통째로 종료됨 — 에러 토스트도 안 뜨고
  그냥 창이 사라짐. CLAUDE.md 원칙("예외 발생 시 앱이 죽지 않고 에러 토스트+로그 기록")을 벗어나는
  케이스: Rust 패닉 훅은 동작해 로그에 남긴 하지만, 이 패닉은 웹뷰/JS 쪽 에러 바운더리로 못 잡음
  (네이티브 이벤트루프 스레드에서 발생).
  ```
  panicked at ...\tao-0.35.3\src\platform_impl\windows\event_loop\runner.rs:371:25:
  cannot move state from Destroyed (...\tao-0.35.3\...\runner.rs:371)
  ```
- **2026-08-10 재현 시 메모:** 이번엔 로그 파일에 패닉 기록이 안 남음(마지막 기록은 재시작 시
  INFO 로그뿐) — 종료 타이밍이 패닉 훅의 파일 쓰기보다 빨랐거나, 이번엔 다른 원인일 가능성도
  배제 못 함. 다만 정황(재시작 직후, 편집 중 사용 중 갑작스런 종료)이 이전 2건과 유사해 같은
  버그로 잠정 분류.
- **영향:** 작업 중 저장 안 된 편집 내용 유실 가능(자동저장 텀 사이 타이핑분).
- **원인 가설:** `tao` 크레이트(Tauri의 Windows 네이티브 이벤트루프 구현)의 창 파괴(Destroy)
  상태 전이 관련 버그로 추정. `npm run tauri dev`로 반복 재기동하는 개발 흐름(HMR·프로세스
  재시작)에서 발생한 것으로 보이나, 프로덕션 빌드에서도 발생하는지는 미확인.
- **2026-08-10 유력 가설(신규, 강한 정황 증거):** `tauri dev`를 껐다가 다시 켤 때 **이전
  실행의 `cargo`/`mdjoa.exe` 프로세스 트리가 완전히 안 죽고 남아있는 채로 새 인스턴스를
  띄우면** 재현되는 것으로 보임. 실제로 이번 재현 직전 `cargo.exe`가 2개 동시에 떠 있었음
  (재시작 시 포트 1420 리스너 프로세스만 죽였는데, `cargo`는 그 자식이 아니라 별도
  프로세스라 안 죽었던 것으로 추정). mdjoa는 `single-instance` 플러그인을 쓰므로, 뒤늦게
  완료된 이전 빌드의 인스턴스가 창을 열려는 시점에 이미 새 인스턴스가 떠 있으면 서로의
  창 파괴/등록 처리가 경합해 이 패닉으로 이어질 수 있음. 이후 `cargo`/`rustc`/`mdjoa.exe`와
  mdjoa 경로를 참조하는 `node.exe`까지 전부 확실히 정리하고 **단일 인스턴스만** 띄운 뒤로는
  재현 안 됨(단, 표본 1회라 확정 아님).
- **다음에 시도**: (1) 위 "다중 인스턴스 경합" 가설 검증 — 의도적으로 `tauri dev`를 두 번
  겹쳐 띄워 재현되는지 확인, (2) 재현되면 원인 확정 → 개발 워크플로 문서(`docs/*.md`)에
  "재시작 전 이전 프로세스 트리 완전 종료" 경고 추가로 충분(코드 수정 불필요, dev 전용
  이슈일 가능성), (3) 재현 안 되면 `tao`/Tauri 버전 업데이트 확인 + 프로덕션 빌드에서도
  발생하는지 확인.
