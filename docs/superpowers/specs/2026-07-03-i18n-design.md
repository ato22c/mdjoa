# MD좋아 i18n(국제화) 설계

- 날짜: 2026-07-03
- 상태: ✅ 구현 완료 (2026-07-04, `feat/i18n`. main의 AI 문서 작업 기능과 병합하며 스윕 범위 확장)
- 배경: 상업화(랜딩·판매 준비)에 따른 영어권 대응

## 1. 전제 (자리 비움 중 권장값으로 진행 — 회신 시 수정)

세 가지 핵심 결정은 사용자 부재로 **권장 옵션**을 채택했다. 다르면 알려주면 문서를 고친다.

1. **대상 언어:** 한국어(ko) + 영어(en) 2개. 단, 3번째 언어를 나중에 추가하기 쉬운 구조로.
2. **범위:** 프론트 UI + 네이티브 메뉴(Rust) + 사용자 노출 에러 메시지 전체 +  도움말에서 표시되는 user-manual.md 
   단 Rust 에러 메시지 국제화는 **마지막 · 분리 가능한 단계**로 둔다(아래 5단계 참고).
3. **언어 선택:** OS 언어 자동 감지 + 설정에서 수동 변경. 기존 `theme`(`light`/`dark`/`system`) 패턴과 동일하게 `language: "system" | "ko" | "en"`.

## 2. 문자열 인벤토리 (실측)

grep 원시 카운트는 주석·JSDoc 때문에 부풀려져 있다. 실제 부담은 코드가 아니라 **영어 번역문 검수량**이므로 정확히 잡는다.

| 대상 | 원시(리터럴) | 실제 UI 추정 | 비고 |
|---|---|---|---|
| 프론트(`src/**/*.tsx,ts`, 테스트 제외) | ~464 | ~300–350 | 나머지는 주석/JSDoc |
| Rust(`src-tauri/src`) | ~87 | 네이티브 메뉴 ~30 + 에러 ~15–20 | 나머지는 주석·테스트 픽스처 |

- **LLM 번역 프롬프트는 국제화 대상 아님.** `src-tauri/src/commands/translate.rs:218`의 프롬프트는 이미 영어이며 한글 카운트에 안 섞임. 문서 번역 기능(`translate.ts`, `lang.ts`)은 UI i18n과 **별개**다. (`lang.ts`는 문서 언어 감지용 — 새 i18n 모듈과 이름 충돌 주의: 새 모듈은 `i18n/`로 명명.)
- 부담 큰 상위 파일: `store/app.ts`(44) · `TopBar.tsx`(36) · `Editor.tsx`(33) · `CommandPalette.tsx`(31) · `MarkdownViewer.tsx`(27) · `AppShell.tsx`(21).
- **사용자 매뉴얼(`docs/user-manual.md`)은 문자열 추출이 아니라 문서 전체 번역**이다. 별도 영어판 `docs/user-manual.en.md`를 만들고 언어에 따라 여는 파일을 바꾼다(4.7). 검수 부담은 여기에 크게 실린다.

## 3. 접근법 비교

| 옵션 | 내용 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **A. 경량 자체 사전 (권장)** | `src/lib/i18n/` — 타입 지정 사전 + `t()` + `useT()` 훅. 의존성 0 | 네트워크 0(제약 부합), 번들 미미, TS로 키 완전성 강제, ~100줄 인프라 | 복수형 엔진 없음(한국어는 복수형 없음, 영어는 소수 → 개별 처리) | ✅ |
| B. i18next + react-i18next | 업계 표준 | 복수형·네임스페이스·지연로딩 | 신규 의존성(~40KB+), 언어 2개엔 과함, 스택 변경 사전협의 대상 | ✗ |
| C. LinguiJS / react-intl | 컴파일타임 추출·ICU | 대규모에 강함 | 빌드 파이프라인·추출 단계 추가. 과잉 | ✗ |

**A 채택.** 언어 2개 + 네트워크 금지 제약 + 린 의존성 원칙(CLAUDE.md)에 부합. "몇 줄로 되는 걸 위해 의존성 추가 금지".

## 4. 아키텍처

### 4.1 프론트 모듈 `src/lib/i18n/`
- `index.ts`
  - `export type Lang = "ko" | "en"`
  - `resolveLang(setting)`: `"system"` → `navigator.language.startsWith("ko") ? "ko" : "en"`, 그 외 그대로.
  - `t(key, params?)`: 중첩 사전에서 키 조회, `{name}` 보간, 미스 시 키 문자열 폴백(개발 중 눈에 띄게).
  - `useT()`: Zustand `settings.language` 구독 → 언어 변경 시 리렌더. 반환 `t`.
- `ko.ts`, `en.ts`: **중첩 객체** 사전(네임스페이스: `menu`, `toast`, `settings`, `welcome`, `review`, `common`…). `en`은 `en: typeof ko` 로 타입 지정 → 누락 키 컴파일 에러.
- 키 명명: 네임스페이스.동사/명사 (`toast.openFailed`, `menu.newFile`).

### 4.2 설정
- `AppSettings`에 `language: "system" | "ko" | "en"` 추가, 기본 `"system"`.
  - `src/types/index.ts` 인터페이스 + `src/store/app.ts` `DEFAULT_SETTINGS`.
  - appdata JSON 저장. 기존 설정 파일에 필드 없으면 로드 시 기본값 병합(기존 `load_settings` 동작 확인 필요 — 없으면 프론트에서 `?? "system"`).
- 설정 모달(`SettingsModal.tsx`)에 언어 선택 UI 추가(테마 선택과 동일 형태).

### 4.3 스토어 / 리렌더
- `settings.language`가 진실의 원천. 파생 resolved lang.
- `useT()`가 language를 구독하므로 언어 변경 → 전 컴포넌트 리렌더(모달·메뉴 포함).

### 4.4 Rust 네이티브 메뉴 브리지
- 메뉴는 `build_app_menu(app, recents)` 한 곳에서 생성, 프론트가 `rebuild_menu`로 재빌드.
- **프론트가 단일 진실의 원천.** Rust에 사전 복제하지 않는다.
  - `build_app_menu(app, recents, labels: &MenuLabels)` 로 `labels` 파라미터 추가.
  - `rebuild_menu(app, labels)` 커맨드 확장 — 프론트가 `t("menu.*")`로 채운 라벨 객체 전달.
  - **언어 변경 시**에도 `rebuild_menu` 호출 → 네이티브 메뉴 즉시 갱신.
  - 앱 시작 시 초기 메뉴도 프론트 로드 후 한 번 rebuild(현재 recents 갱신 흐름 재사용).
- 단축키 힌트(`(Ctrl+N)` 등)는 `platform.ts` MOD_LABEL과 결합(이미 mac=⌘/win=Ctrl 추상화됨).

### 4.5 Rust 에러 메시지 (분리 가능 · 마지막 단계)
- 현재 `Err("한글")` → 프론트 토스트. 국제화하려면 **에러 코드/키**로 전환:
  `Err("file_too_large")` + 필요 시 파라미터 → 프론트 `t("error.fileTooLarge", {size, max})`.
- 모든 커맨드의 에러 계약을 건드리는 유일한 고변경 지점 → **최종 · 분리 단계**. 사용자가 이 단계를 미뤄도 나머지(메뉴·설정·환영·토스트)는 정상 출시 가능.
- 대상은 ~15–20개(사용자 노출분만). 파싱 로직 없이 `.map_err`에서 키만 반환.

### 4.6 상대 시간 (`N분 전`)
- `Intl.RelativeTimeFormat`(네이티브) 사용 — 영어 복수형(`1 minute`/`2 minutes`) 자동 처리, 수작업 복수형 회피. TopBar의 커스텀 포맷 교체.

### 4.7 사용자 매뉴얼 (도움말 F1)
- 현재: `docs/user-manual.md`가 Tauri 번들 리소스(`tauri.conf.json` resources). `resolveResource("docs/user-manual.md")` → `openFile(path)`로 뷰어에 문서로 표시. 호출부 **3곳**: `AppShell.tsx`(F1 + `menu:open-manual`), `HamburgerMenu.tsx`, `AboutModal.tsx`.
- 국제화:
  - 영어판 `docs/user-manual.en.md` 추가, `tauri.conf.json` resources에 함께 번들.
  - 경로 선택 헬퍼 1개 신설: `manualResource(lang)` → `en`이면 `docs/user-manual.en.md`, 아니면 `docs/user-manual.md`. **3개 호출부를 이 헬퍼로 통합**(현재 중복된 `resolveResource(...)`/실패 토스트 코드를 한 곳으로).
  - 실패 토스트("매뉴얼을 찾을 수 없습니다")도 `t()`로.
  - 영어 매뉴얼 본문 = 한국어 매뉴얼 번역(내가 초안 → 사용자 검수). 문서 번역 기능으로 초벌 후 사람 검수 가능.
  - 폴백: 선택 언어 매뉴얼이 없으면 한국어판으로 폴백(번들 누락 안전장치).

## 5. 단계별 계획 (사용자 가시 가치 순 · 항상 실행 가능 유지)

각 단계 끝은 빌드·테스트 통과 상태.

1. **인프라 + 파일럿** — `src/lib/i18n/`(index/ko/en), `AppSettings.language`, `SettingsModal` 언어 선택 UI, `useT()`. 파일럿 1개 컴포넌트(예: `WelcomeScreen` 또는 `TopBar`) 전환으로 배선 검증. 완성 기준: 언어 토글 시 파일럿 컴포넌트가 즉시 바뀜.
2. **네이티브 메뉴** — Rust `labels` 브리지, 언어 변경 시 rebuild. (고가시성·소량 ~30)
3. **프론트 스윕 (본체)** — 상위 부담 파일부터 전 컴포넌트/토스트/모달 전환. 파일 단위로 진행, 각 파일 완료 시 완성 가드(6절) 통과.
4. **상대 시간·기타 포맷** — `Intl.RelativeTimeFormat` 등 포맷 계열.
5. **사용자 매뉴얼 영어판** — `manualResource(lang)` 헬퍼로 3개 호출부 통합, `docs/user-manual.en.md` 작성·번들, 폴백. (4.7)
6. **(분리 가능) Rust 에러 메시지** — 에러 코드 전환. 미루기 가능.

## 6. 검증 방법 — 완성 가드 (핵심)

`en = typeof ko`는 **사전 두 개가 짝이 맞는지**만 증명한다. 컴포넌트에 남은 하드코딩 한글은 타입 통과로 그냥 실려 나간다 → 이게 진짜 리스크.

- **완성의 기준 = "사용자 노출 경로에 한글 리터럴 0"** 을 grep/eslint 가드로 강제.
  - 파일 단위 완료 체크: 해당 파일에 한글 문자열 리터럴 없음(주석은 허용).
  - CI 게이트: 사용자 노출 경로(components/, store 등) 한글 리터럴 검출 시 실패.
  - 예외 화이트리스트: `i18n/ko.ts`, 주석, 문서 번역 프롬프트/로직, 테스트 픽스처.
- 단위 테스트(CLAUDE.md 규칙 — 핵심 로직):
  - `en` 키가 `ko` 키를 모두 포함(완전성).
  - `t()` 보간(`{name}`) 정상.
  - 미스 키 폴백 동작.
