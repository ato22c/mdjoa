# 외부 파일 변경 — 동작 시나리오 & UX

> 작성: 2026-06-14 · 관련 태스크 #3/#4 · 핵심 가치: "AI가 수정한 문서를 즉시 갱신·확인"

다른 에디터/AI 에이전트/Finder가 디스크의 `.md`를 **추가·수정·삭제**했을 때 MD좋아가 어떻게 반응하는지 정의한다. 두 가지 감시가 동작한다:

- **열린 문서 감시** (`useFileWatcher` → AppShell, 보기·편집 **모두**): 현재 열린 파일의 부모 폴더를 보고, `store.refreshOpenFileFromDisk()`가 상황별로 처리.
- **폴더 감시** (`useFolderWatch` → 파일트리): 폴더 전체를 보고 트리를 디스크와 동기화(추가→나타남, 삭제→사라짐) + 변경 종류 뱃지.

**원칙:** ① 트리는 항상 디스크 실제 상태 ② 미저장 편집은 절대 자동으로 잃지 않음 ③ 안전할 때만 자동 반영 ④ 모순 없는 인식(삭제된 파일이 트리에 남지 않음).

---

## 1. 열린 문서 (현재 보거나 편집 중인 파일)

결정 로직: `src/lib/externalChange.ts` `decideExternalChange()` (순수 함수, 단위 테스트 `externalChange.test.ts`).

| 상황 | 보기 모드 | 편집 모드 |
|---|---|---|
| **수정됨** | auto-reload ON → 조용히 다시 읽고 "업데이트됨" 깜빡 / OFF → "외부에서 변경됨 · [새로고침]" 배너 | 미저장 편집 **없음** → 디스크 내용 자동 반영("외부 변경이 편집기에 반영되었습니다") / 미저장 편집 **있음** → "외부에서 변경됨 — 저장 시 내 편집으로 덮어씀 · [디스크 내용 불러오기]" 배너 (자동 덮어쓰기 안 함) |
| **삭제됨** | "이 문서가 외부에서 삭제되었습니다 — 내용 보존 · [현재 내용으로 다시 저장]" 배너 (내용 계속 표시) | "외부에서 삭제됨 — 저장하면 다시 생성됩니다" 배너 (버퍼 보존, ⌘S로 재생성) |
| **삭제 후 같은 이름으로 재생성** | 부모 폴더를 감시하므로 재생성 이벤트 수신 → 존재 확인 → 자동 reload/reflect, 삭제 배너 해제 | 동일하게 복구(편집 없으면 반영, 있으면 충돌 배너) |

내 **자신의 저장**(auto-save 포함)으로 인한 이벤트는 디스크 내용 == 현재 내용이라 `none`으로 무시 → 불필요한 깜빡임/루프 없음.

## 2. 폴더의 다른 파일 (열려 있지 않은 파일)

종류 판별: `src/lib/fsEventKind.ts` `classifyFsEvent()` (테스트 `fsEventKind.test.ts`). macOS FSEvents가 "any"만 줄 때는 `file_exists`로 보정.

| 상황 | 트리 동작 |
|---|---|
| **추가됨** | 트리에 **자동으로 나타남**(재나열) + **초록 점** 뱃지("외부에서 생성됨") |
| **수정됨** | **호박색 점** 뱃지("외부에서 변경됨"). 생성 뱃지는 sticky(이후 수정해도 생성으로 유지) |
| **삭제됨** | 트리에서 **사라짐**(재나열) + 뱃지 제거 — 삭제된 파일이 목록에 남지 않음 |

뱃지는 그 파일을 **열면 사라짐**(현재 보는 파일은 뱃지 안 함). 전부 해제는 기존 동작 유지.
