## 0. 이 문서의 범위

1차 제안(`FEATURE-PROPOSALS.md`)의 Tier 1·일부 Tier 2가 **이미 구현 완료**됐다(아래 §1 코드 근거).
2차 기획은 그 위에서 **AI 개발 워크플로에 실제로 유효한 다음 단계**만 선별한다.

원칙은 그대로다 — **콘텐츠 퍼스트 미니멀 · 경량 · 기능 과잉 금지.**
무겁거나 타깃과 안 맞는 것은 본문에서 **"비권장/보류"로 명시**하고 이유를 적는다.
"있으면 멋있다"는 채택 사유가 아니다. 채택 기준은 단 둘:

1. **다수 MD를 읽기·열기·AI 수정 추적**이라는 핵심 니즈에 직접 기여하는가
2. **UI 크롬을 안 늘리고**(상단 메뉴바 없음·아이콘 3~4개), **Tauri+React+markdown-it+Rust로 자연스러운가**

### A. AI 변경 요약 패널 — *가장 차별적, T1*

| 항목 | 내용 |
| --- | --- |
| **해결 문제** | 에이전트가 **여러 MD를 한 번에 수정**하면 "무엇이·어디가 바뀌었나"를 파일별로 일일이 열어 봐야 한다. 현재는 트리에 "바뀜" 뱃지만 뜬다(파일 목록 수준). |
| **동작 개요** | 이미 있는 `changedFiles`(폴더 워처가 채움)를 **목록 패널**로 승격: 변경된 MD를 한곳에 모아 보여주고, 각 항목 클릭 시 **그 파일의 직전 본 내용 ↔ 현재 디스크 내용 줄 단위 diff**를 인라인으로 표시. "모두 확인" 버튼으로 뱃지 일괄 해제. |
| **가치** | **상.** 핵심 니즈("AI가 수정한 문서를 즉시 갱신·확인")의 정확한 가운데. 1차 변경 하이라이트의 자연스러운 확장. |
| **무게** | 🟡 중간. diff는 이미 있는 `textDiff.ts`(LCS) 재사용. "직전 본 내용" 스냅샷은 **세션 메모리에만**(디스크 영속화 X) 보관 → 무게/복잡도 억제. 인덱스·DB 불필요. |
| **스택 적합성** | 높음. `changedFiles`(Zustand)+`textDiff.ts`+React 패널. 새 Rust 커맨드 불필요(읽기는 기존 `read_file`). |
| **백로그 관계** | **#11(스냅샷 히스토리)·#12(두 파일 diff)의 경량 대체**. "버전 영속 저장"(#11) 없이 **세션 내 직전상태 1개만** diff → 무거운 #11을 상당 부분 흡수. #12와 달리 "두 임의 파일"이 아니라 "한 파일의 변경 전후"라 스코프가 작다. |
| **미니멀 가드** | 패널은 **변경이 있을 때만** 노출(평소 숨김). 상단 아이콘 1개 또는 트리 뱃지 클릭으로 진입. diff는 인라인(별도 창 X). |

### D. 합산 토큰 + 컨텍스트 윈도우 게이지 — *T2, 토큰카운트 확장*

| 항목 | 내용 |
| --- | --- |
| **해결 문제** | 단일 문서 토큰은 표시됨(완료). 그러나 **"이 문서 세트를 컨텍스트로 넣으면 윈도우에 들어가나"**는 모른다. 여러 컨텍스트 문서를 합쳤을 때 용량 감이 필요. |
| **동작 개요** | Quick Open/컨텍스트 섹션에서 **여러 파일 선택 → 합산 토큰** 표시. 선택한 모델 윈도우(예: 200k) 대비 **막대 게이지**(예: 38k / 200k = 19%). 폴더 전체 합산도 옵션(상한·취소 가능). |
| **가치** | **상.** AI-dev 특화의 정점. 단일 토큰 카운트의 자연스러운 다음 수.   |
| **무게** | 🟡 중간. 토크나이저(완료)는 lazy-load BPE — **N개 파일 합산은 직렬·취소 가능**하게. 폴더 전체는 상한(예: 파일 수/총 바이트)으로 보호. 정확값이 느리면 **문자/4 근사로 먼저 채우고** 정확값으로 갱신(이미 TopBar가 쓰는 패턴). |
| **스택 적합성** | 높음. `tokenizer.ts`(완료) 재사용. 읽기는 `read_file`. 윈도우 상수는 설정 JSON. |
| **백로그 관계** | 완료된 토큰 카운트의 확장. C(컨텍스트 섹션)·G(워크스페이스)와 강하게 연계(선택 단위가 같음). |
| **미니멀 가드** | 게이지는 **다중 선택 시에만** 표시. 모델 프리셋 소수(예: 128k/200k/1M) + 직접 입력. 비용($) 추정은 **넣지 않음**(가격 변동·텔레메트리 인상 → 정체성 충돌). |

## 3. 비권장 / 보류

### H. 로컬 스냅샷 히스토리(#11) — **비권장(보류)**

- **사유 1 (정체성):** 버전을 디스크에 영속 저장·관리·비교·되돌리기 = "경량 뷰어"가 아니라 **경량 VCS**. 1차 무게표에서 이미 🔴. "기능 과잉 금지" 정면 위반.
- **사유 2 (중복):** AI 개발 환경엔 **git이 이미 있다**. 에이전트 변경 추적의 1급 도구는 git diff/commit이며, 뷰어가 별도 버전 저장소를 두는 것은 신뢰성 리스크(저장 위치·정리·용량)만 추가.
- **사유 3 (대체 존재):** "직전과 비교"라는 실효 수요는 **제안 A(세션 내 변경 전후 diff)**가 디스크 영속화 없이 충족한다.
- **결론:** #11은 **보류 유지**. 정말 필요하면 "git이 있는 폴더에서 `git`을 호출해 보여주는" 얇은 통합으로 재검토(별도 기획) — 자체 스냅샷 저장소는 만들지 않는다.

### I. 그래프 뷰 · 플러그인 생태계 · DB/임베드 — **제외(1차 결정 유지)**

- 무게 🔴, 콘텐츠 퍼스트 미니멀과 정면 충돌. 1차 "제외 권장" 그대로 유지. 백링크(F)로 역참조 정보는 충분.

### 창 분할(인앱 2-pane) — **보류(별도 문서 결론 인용)**

- `split-view-review.md` 결론대로 **보류.** "두 문서 비교"는 제안 B(유니파이드 diff)와 멀티윈도우(#2)가 흡수. 본문 폭을 쪼개는 인앱 분할은 콘텐츠 퍼스트와 충돌.

### 비용($) 추정 / 사용량 텔레메트리 — **제외**

- 토큰 게이지(D)에 비용 환산을 붙이고 싶을 수 있으나, 가격은 자주 바뀌고 정확성 보장이 어렵다. 또한 **텔레메트리/네트워크 금지** 원칙과 인접해 오해 소지. **토큰·윈도우 비율까지만.**

## 7. L — `.claude` 스킬 목록 보기 (상세 후보 기획)

| 항목 | 내용 |
| --- | --- |
| **해결 문제** | agentic AI 개발자는 프로젝트마다 `.claude/skills/<name>/SKILL.md`를 다수 관리한다. 어떤 스킬이 있는지·무슨 일을 하는지(설명)를 한눈에 보려면 매번 트리를 파고들어 각 `SKILL.md`를 열어야 한다. |
| **동작 개요** | 폴더를 열 때 `.claude/skills/` 존재를 감지하거나, `.claude/`(혹은 `.claude/skills/`) 폴더 자체를 열면 → 하위 `*/SKILL.md`를 스캔해 frontmatter `name`/`description`을 뽑아 **사이드바 "스킬" 목록**으로 표시. 항목 클릭 시 해당 `SKILL.md`를 뷰어로 연다. |
| **가치** | **상.** "쉽게 열기" + 타깃(스킬 작성자) 특화. 컨텍스트 자동 그룹(C, 완료)의 자연스러운 확장. |
| **무게** | 🟡 중간(난이도는 낮음). 폴더 1회 스캔(`list_dir`) + `extractFrontmatter`(완료) 재사용. 인덱스·워처 추가 없음. 폴더 변경 워처(완료)에 얹어 갱신 가능. |
| **스택 적합성** | 높음. `ContextSection.tsx` 패턴 복제, `lib/markdown.ts:extractFrontmatter` 재사용. 새 Rust 커맨드 불필요. |
| **백로그 관계** | C(컨텍스트 자동 그룹)와 역할 분리: C=문서 컨텍스트(CLAUDE.md 등) / L=스킬 정의(SKILL.md). 향후 `.claude/agents`·`commands`로 확장 여지. |
| **미니멀 가드** | `.claude/skills`가 없으면 섹션 **완전 숨김**(크롬 0). 자동 그룹과 동일한 노출 규칙. |

**결정 필요(착수 전):**
1. **진입 트리거** — (a) 폴더 열기 시 `.claude/skills` 자동 감지만 / (b) `.claude` 폴더를 직접 여는 것도 1급 지원(트리에서 `.claude`로 진입 시 스킬 목록 화면). 사용자 요청은 **둘 다 ((a)+(b))**.
2. **표시 위치** — 기존 "컨텍스트" 섹션에 통합 vs 별도 "스킬" 섹션 신설.
3. **범위 확장** — `.claude/agents/*.md`·`.claude/commands/*` 까지 묶을지(이 프로젝트엔 `.claude/agents/`가 이미 존재).
4. **숨김 폴더 처리** — 트리/탐색기에서 `.claude` 등 점(.)폴더가 현재 보이는지 확인(스캔 경로만이면 표시 무관).
